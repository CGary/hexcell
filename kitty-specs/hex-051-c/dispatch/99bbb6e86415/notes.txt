### 1. Rebuilding `reservas` with Nullable Conversations
To allow a catalog ingestion to reserve budget without a dummy conversation (which would distort per-conversation metrics), the table `reservas` was rebuilt to make `id_conversacion` nullable:
* **The File:** [0004-reservas-sin-conversacion.sql](file:///home/gary/dev/hexcell/worktrees/HEX-051-c/crates/hexcell-storage/migraciones/sesiones/0004-reservas-sin-conversacion.sql)

#### CONCEPTUAL LESSON: SQLite Transactions & Foreign Key Enforcement
* **Why not `PRAGMA foreign_keys = OFF`?** In SQLite, disabling foreign keys is a **NO-OP** inside an active transaction. Because the migration runner wraps each rung in an `unchecked_transaction`, the standard rebuild step is impossible here.
* **The Tool that Works:** `PRAGMA defer_foreign_keys = ON;` is used instead. This defers the foreign key checks until the transaction is committed, allowing us to safely recreate the parent `reservas` table and copy data from the old one without triggers or foreign keys aborting immediately.
* **The Integrity Gate is Critical:** SQLite's `PRAGMA defer_foreign_keys = OFF` **silently discards** pending deferred violations rather than validating them. To prevent ledger corruption (e.g. orphaned `movimientos` rows), we implemented an explicit active check:
  ```sql
  UPDATE saldo
  SET disponible = CASE
      WHEN (SELECT count(*) FROM pragma_foreign_key_check) = 0 THEN disponible
      ELSE 'Violacion de clave foranea detectada al reconstruir la tabla reservas en la migracion 0004'
  END
  WHERE id = 1;
  ```
  Since `saldo` is a `STRICT` table and `disponible` is an `INTEGER`, attempting to write a `TEXT` error message on any violation triggers a strict type error, forcing SQLite to roll back the entire transaction.

### 2. Views: Separating Cost Aggregations
* **`consumo_por_conversacion`** is updated to filter out `NULL` conversation rows so that Rust code reading this view does not hit runtime conversion errors when mapping into a non-optional `String`.
* **`consumo_de_ingesta`** aggregate is introduced for `NULL` conversation rows. To avoid returning `NULL` when no ingestion rows exist (which would fail reads), the aggregate uses:
  ```sql
  COALESCE(SUM(CASE WHEN r.estado = 'conciliada' THEN r.monto_reservado - COALESCE(m.monto, 0) ELSE 0 END), 0)
  ```
  Since this lacks a `GROUP BY` clause, it is guaranteed to return exactly one row (holding `0` on empty database), matching `AC-4`.

## What
Refactorización de la base de datos `sessions.db` (migración 0004) para hacer que el campo `id_conversacion` en la tabla `reservas` sea nullable, permitiendo reservas de presupuesto para ingestas de catálogo (sin conversación asociada). Una ingesta de catálogo no pertenece a ninguna conversación y crear una conversación artificial corruptora fue rechazado. 1. En este workspace, `PRAGMA foreign_keys` viene activado por defecto en conexiones raw porque la amalgamación de SQLite se compila con `-DSQLITE_DEFAULT_FOREIGN_KEYS=1`.
